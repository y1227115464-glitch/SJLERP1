## 1. 目标

把采购、收货、发货和库存记录串联成可实际使用的流程。默认支持供应商到仓以及仓库至 FBA / 其他仓库两段物流；已通过异步问题征询用户，可按回复调整。

本次交付采购单、分批发货和接收、物流事件、仓库档案、库存余额、占用、流水及手工调整。金额审批规则、应付核销、质检退货、装箱和运费分摊、亚马逊快照导入与销量补货属于既有路线图后续范围，本次不标为完成。FBA 仓记录为人工接收的账面数量，不代表亚马逊实时可售库存。

## 2. 方案

现状：共享商品 Product、Supplier 和 SupplierQuote，没有采购/发货/仓库/库存实体。
变化：新增 supply 模块，含 Warehouse、PurchaseOrder/Line、Shipment/Line/Event、InventoryBalance/Movement、幂等操作记录。

- 采购草稿可编辑，提交后锁定数量金额，记录供应商、店铺、采购日期、预计到货、商品、数量、单价、币种和备注。可取消尚未交付且未被物流分配的余量。
- 从已提交采购单安排分批供应商发货；分配总量不超过未收货量。供应商直发 FBA 可直接选择 FBA 目的仓。
- 仓库发货计划创建时占用可用量；发出时扣实物并释放占用；取消待发计划释放占用。已发出货物按分批接收减少在途、增加目的仓库存。
- 每次物流操作记录事件、时间、操作者和说明。可维护承运商、运单、Amazon Shipment ID、预计到货；展示超期。
- 库存以店铺 + 仓库 + 商品为唯一键。实物 ≥ 占用 ≥ 0，可用=实物−占用。在途从已发出但尚未接收的明细聚合，和仓内数量不重复。
- 入库、出库、占用/释放、期初/调整均产生不可编辑流水；调整需要原因，扣减不能动用已占用量；库存事务使用行锁和条件更新，不调用缓存。
- 所有库存过账、建单请求带 request_id。相同请求重试返回当前单据且不重复记账；同 token 不同负载拒绝。
- 复用 RBAC：经理管理全部授权店铺采购物流库存；仓库可收发货和调整，采购金额不可见；财务看采购金额、维护采购，物流库存只读；运营查看授权店铺物流库存；管理员全范围。共享仓库档案的启停/名称不改变货权。
- 列表分页 20，API 上限 200；选择器搜索上限 30。单据最多 100 行。关联通过批量查询加载；索引覆盖店铺、状态、日期、仓库商品唯一键及关联外键。

## 2.5 结构健康度

结论：现有目录可继续使用，新建 `app/supply/` 和独立前端页面；不向 models.py / routes.py 继续堆主体业务。接入点只有模型注册、路由注册、权限和导航。卸载需先处理业务数据，再移除这些接入点与迁移，既有商品供应商行为不变。

## 2.6 API

统一 `/api/v1` + session cookie / Origin / X-Requested-With / 写操作 X-CSRF-Token。

- `/warehouses` GET/POST、`/{id}` PATCH。
- `/purchase-orders` GET/POST、`/{id}` GET/PATCH、`/{id}/confirm` POST、`/{id}/cancel` POST。
- `/shipments` GET/POST、`/{id}` GET/PATCH、`/{id}/dispatch`、`/{id}/cancel`、`/{id}/events`、`/{id}/receive` POST。
- `/inventory`、`/inventory/movements`、`/inventory/summary` GET；`/inventory/adjustments` POST。

例：采购 100 件，建供应商货件 60 件并收货 40 → 采购已收 40、仓存 40、在途 20；仓库计划发 25 → 可用 15、占用 25；发出后仓存 15、该货件在途 25；接收 20 → 目的仓增加 20、该货件在途余 5。

## 3. 验收契约

1. 新建/编辑/提交采购单，金额按 Decimal 精确计算；错误供应商、重复商品、负数/非整数数量被拒绝。
2. 两次分批供应商发货不能超采购量；部分收货/余量取消正确；取消不能吞掉已发在途。
3. 采购收货、仓库占用、出库、接收数量按上述例子守恒，流水可查。
4. 双击/重试不重复建单或过账；并发出库不超库存；并发接收不超发货量。
5. 库存调整有原因且不可产生负库存/侵占占用；历史流水没有编辑删除接口。
6. 普通用户跨店列表、详情、写入、摘要均不泄漏数据；仓库账号看不到采购金额。
7. 前端有三个入口、表单校验、分页筛选、状态/超期展示、物流时间线、错误反馈；切店关闭旧详情。
8. 迁移在 SQLite / PostgreSQL 通过，原有测试通过，浏览器完成关键流程；局域网部署能持续访问。
