# 发布说明

当前仅完成代码、迁移脚本和隔离测试，未迁移业务数据库或发布运行服务。

1. 按现有运维流程备份当前 PostgreSQL 数据库并核对可恢复性，暂停业务写入。
2. 在项目根目录执行 `.venv/bin/python scripts/dev.py migrate`，确认 Alembic head 为 `61cd940be820`。该命令使用现有 `.env`，不会替换配置。
3. 执行 `npm --prefix apps/web run build`，部署 Web 并重启 API 及导入同一模型的 worker/scheduler。
4. 在「商品管理 → 详情 → 售卖店铺」维护各商品实际售卖范围，并核对「采购报价」中商品与供应商的启用关联。历史商品不自动绑定全店铺。
5. 既有采购单的跟进初始值为未付款/未收票，最后跟进为空，须人工核实后更新；不得将默认值当成历史财务结论。
6. 验证新增采购候选交集、草稿提交、付款与发票保存、同路线待发货件合并后发货及收货数量。

不新增服务、环境变量、队列或定时任务，不执行真实付款或开票。

回滚优先回退应用并保留新增字段/表，避免删除新增跟进记录或合并来源信息。若已发生合并，不应直接回退数据模型；需停止写入并根据备份与期间业务流水制定恢复方案。迁移降级仅用于隔离测试或确认无新数据的环境。
