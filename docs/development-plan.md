## 1. 建设目标与范围

为书剑录建立多人使用的中文 Web ERP，覆盖美国站、多店铺、FBA 为主的经营和供应链流程。原一期、二期全部纳入本轮开发，按依赖分批交付。

已确认的订单和广告维护流程：亚马逊后台导出文件 → 人员上传 ERP → 校验、匹配及确认 → 数据入库 → 更新分析与待办。

库存、交易、结算、仓储及其他费用默认规划为报表导入，具体格式随真实样本确定；采购、仓库、物流、收付款和运营任务在 ERP 录入。

范围依据：[ERP 功能规划](erp-product-plan.md)。技术实施依据：[Web ERP 技术方案](erp-technical-plan.md)。

主要操作按 [灵活作业与工作台待办](weekly-operations-workflow.md) 调整：采购、分析、发货独立使用，标准流程仅通过事件和周期生成可调整待办。2026-09-09 已完成W0待办和提醒，后续未勾选任务继续推进。

本轮最终交付必须覆盖：店铺、用户权限、商品、成本、数据导入、销售订单、广告、利润、财务、库存仓库、补货、采购供应商、头程入仓、工作台与任务。

API 自动同步、广告操作写回、自动改价、高级预测及完整新品开发系统作为后续扩展。

周度改版细化 M6-01/05/06：现有单货件上方增加可选发货批次及来源分配，支持多采购来源与多 Amazon 货件；计划量、实发量、接收量独立。补货保护期包含完整提前期、7 天复查间隔及安全量，并单独检测到货前断货，实际运输天数未配置时提示自动估算缺口，保留手动填量采购。

## 6. 验证策略

| 验证对象 | 必测业务情形 |
| --- | --- |
| 数据与权限 | 两店同名 SKU、直接访问其他店铺资源、跨主体关联、字段隐藏及导出权限 |
| 导入 | 相同文件、重叠日期、状态更新、广告延迟回补、不同报表重复事实、任务中断和重试 |
| 金额 | 原币与换算、舍入尾差、缺成本、未知费用、退款、广告扣款重复、公司费用分摊 |
| 库存 | 期初切换、部分到货、供应商直发、并发出库、调拨、报损、退货、部分接收与在途重复 |
| 灵活作业与提醒 | 周一09:00一次下单、发货前2天/当天、每日15:00/周五周期、改期/取消/拆批、提前完成、停机恢复与去重；取消提醒或跳过跟进不锁业务；计划/实发/接收数量守恒 |
| 月结 | 资料缺失、差异未清、结账锁定、事后费用、撤回导入、反结账和调整版本 |
| 界面 | 登录→导入→纠错→分析→导出；采购→收货→发货→接收→成本→月结 |
| 运行 | 大文件资源限制、可观察进度、后台任务恢复、数据库迁移和备份恢复 |

验证随模块推进，不拖到 M8 才进行。金额等关键结果以确认样例和独立核对值为准，不能仅用实现自身生成的结果作为验收答案。
