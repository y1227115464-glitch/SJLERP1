# 销售数据分析

品牌推广广告日报也参与实际广告费：请先在「广告数据 → 品牌广告分摊」按店铺和活动名称维护 SKU 与百分比（合计 100%）。配置应用于全部历史及后续日报；未配置活动会显示待分摊金额，并将受影响店铺的实际广告费和推广后利润留空。详见 [品牌推广导入和分摊规则](amazon-report-imports.md#品牌推广活动报告)。

原「销售记录」入口改名为「销售数据分析」。包含「销售数据分析」与「订单明细」两个页签，原订单查询、币种/状态核对和来源批次追溯继续保留。

## 数据与筛选

- 数据来自已确认导入的销售订单、广告日报，不写入示例经营数据。
- 按店铺、日期、精确 SKU 或 SKU 关键词筛选；列表默认按 SKU 字母升序（A–Z）排列，也可切换销量、销售额、利润、利润率及广告费排序。排序应用于全部筛选结果后再分页。
- 默认选择「最近7天」，不含当天，按 PDT 截至昨天向前计算完整 7 天；日期面板的「含当天」默认不勾选，可自行调整日期或查看全部日期。
- 默认选择「全部未取消商品」；可切换「已发货商品」，仅统计订单状态为 Shipped / Partially Shipped、商品状态为 Shipped 的明细。两种模式均排除订单或商品状态为 Cancelled / Canceled 的记录。
- 订单按 PDT（全年固定 UTC−7，不切换冬令时）下单日期筛选，广告按来源日报日期筛选。USD 保持原值，CAD、MXN 按页面显示的固定分析汇率折算，销售和广告使用相同汇率。默认沿用周利润口径 1 USD = 1.36 CAD / 17.66 MXN，可针对当前分析调整；不是实时汇率。不支持或缺少币种的来源行数单独提示。

销售分析、订单明细、汇总及 SKU 候选使用相同日期边界：起始日 PDT 00:00（UTC 当日 07:00）包含，结束日次日 PDT 00:00（UTC 次日 07:00）不包含。快捷日期的「今天」也按固定 PDT 计算。原始时间戳仍保存为 UTC，不需要重新导入；本次筛选时区调整不改变既有费用版本按 UTC 下单日期匹配的规则。
- 店铺与 SKU 联合分组，广告存在但没有订单的 SKU 仍会显示。沿用已确认周利润规则：CMBQ-XXL-250S、CMBQ-XXXL-250S、CMBQ-XS-250S、CMBQ-M-250S、CMBQ-S-250S、CMBQ-XL-250S 归并为 CMBQ-L-250S，费用也统一维护；可展开查看原始 SKU。其他 SKU 精确关联，不推断相似名称的对应关系。gfss 两种颜色保持独立。
- 广告使用已导入日报，历史多日区间汇总不再叠加。没有任何广告日报的店铺/所选期间，广告费用及广告后利润留空；已有日报中未出现的 SKU 广告费显示 0。系统不能据此证明每一天报表都完整，使用者需核对导入期间。

## 计算口径

所有单件费用单位 USD，使用 Decimal 计算。每个店铺 SKU 的费用与销售额先汇总再四舍五入至分，利润使用这些分位金额相减，合计为全部筛选行相加。

| 列 | 公式 / 来源 |
| --- | --- |
| 店铺 SKU | 同店铺内按上述归并规则汇总 Seller SKU |
| 销量 | 所选订单商品行 quantity 之和 |
| 产品成本、头程及入库配置费 USD | 按下单日适用单件成本及另计入库费 × 对应销量 |
| FBA 派送费 USD | 每条订单按优惠前单件售价选择 ≤ $9.99 或 > $9.99 档位，再按下单日适用单件物流费 × 对应数量汇总 |
| 亚马逊佣金 USD | 商品销售额 × 对应费用版本佣金率，未配置时默认预估 15% |
| 销售利润 USD | 销售额 − 产品成本/头程/入库费 − FBA 派送费 − 佣金 |
| 亚马逊销售额 USD | 商品金额 − 商品优惠；原行金额不再次乘销量 |
| 销售利润比（未扣除推广费用） | 销售利润 ÷ 销售额 |
| 实际广告费 USD | 同店铺、SKU 与所选期间广告日报 spend 之和 |
| 扣除推广实际利润 USD | 销售利润 − 实际广告费 |
| 实际利润率 | 扣除推广实际利润 ÷ 销售额 |

销售额不含运费、礼品包装费和税，与「订单明细」中的不含税订单净额口径不同。广告归因销售额不叠加到订单销售额。此分析仍使用成本与派送费参数、预估佣金，不能作为实际结算/月结利润。订单导出不能完整表达结算退款与其他费用。

SKU 销售与利润列表每页显示 200 条，不足 200 条时显示实际数量。数据区最大高度为窗口高度的 60%，且不超过 640px，表头与合计固定；鼠标在数据区滚动时优先滚动表内数据，到达顶部或底部后继续滚动会接续页面滚动，表格外滚动直接作用于页面。合计按全部筛选结果计算，不受分页影响；合计利润率以合计利润除以合计销售额重算，不平均 SKU 利润率。销售额为 0 时利润率按约定显示 0。缺少销售额、单件成本、入库费确认或派送费时，受影响金额与利润保留为空，合计相应字段也为空，避免用部分成本高估总利润。

点击 SKU 左侧「+」展开所选店铺、SKU 在筛选期间的销售与利润明细，可切换「按天 / 按周 / 按月 / 按年」。起止日期均计入天数：1–14 天默认按天，15–30 天默认按周，31–180 天默认按月，超过 180 天或全部日期默认按年；更改日期后重新应用默认粒度。周为周一至周日，月、年按自然周期，首尾只统计所选范围内的数据。没有订单的期间也列出，保留仅有广告费用的期间；各期间没有广告日报时，广告费及广告后利润显示待确认。全部日期按该 SKU 已有数据覆盖的周期展示。

展开明细沿用主表的订单范围、汇率、SKU 归并及费用版本规则，订单按固定 PDT 日期归组，费用仍按 UTC 下单日期匹配。每个周期独立汇总金额后四舍五入，利润率以周期利润除以销售额重算；品牌广告按周期分摊到分，明细金额相加与整段汇总可能存在分位舍入差异。原有来源 SKU、来源行数及费用查看入口保留。

## 费用维护

点击「费用设置 → 产品成本与佣金」，可按 SKU 搜索、添加生效日期版本、编辑现有版本。每个版本包含：适用店铺（或通用）、精确 SKU、生效日期、产品及头程单价、另计入库费、佣金率和来源说明。原 FBA 单价作为历史单档费用保留展示，新物流费在独立页签维护。

两类费用均可删除版本：「产品成本与佣金」在行末点击「删除」；「亚马逊物流费」进入 SKU 的「历史版本」后删除对应版本。删除前展示具体范围、日期与金额，操作按维护权限及版本号校验并记入日志。删除产品成本版本会一并移除该版本的产品及头程、另计入库、佣金率和历史单档 FBA 值；独立物流费版本仍保留。相关订单重新选择此前适用版本或通用配置，无成本时标记待补充并将相关利润留空，佣金沿用现有默认 15% 规则。需要恢复时重新新增版本。

- 下单日存在店铺专用版本时优先使用该版本，否则使用通用版本；分别选择不晚于下单日的最近生效日期。
- 专用版本有空值时不从通用版本补值，以免混用来源。留空表示未知；确认无费用时填写 0。
- 产品单价已经包含入库费时，另计入库费填 0。
- 新增生效日期保留先前成本口径；修改现有版本会重算该版本的适用期间。并发修改检查版本号，旧页面提交会收到刷新提示。
- 查看分析与费用要求 reports.view 和 costs.view；运营仍可看订单明细。管理员可维护通用费用；有 quotes.manage 的经理和财务可维护授权店铺费用。写入要求会话 CSRF 校验并记录审计，审计摘要不显示金额。

### 亚马逊物流费（按售价分档）

左侧「亚马逊物流费」提供所有商品的维护入口，也可从「费用设置 → 亚马逊物流费」进入。列表包含商品档案 SKU、可见订单及广告 SKU、已维护成本与物流费 SKU；没有订单或没有费用的商品也可以维护。列表按原始 SKU 精确匹配，不自动推断商品内部 SKU 与不同 Seller SKU 的关系。

商品状态可选「全部、启用中、已停用」，默认「启用中」，按精确 SKU 对应商品档案的启停状态筛选；未建档的 SKU 仅在「全部」中展示。筛选作用于完整目录后再分页。

「新增物流费版本」通过可搜索的 SKU 下拉框选择商品，选项显示 SKU、所属店铺及商品名称，并跟随顶部店铺筛选。归属沿用商品品牌与店铺品牌的一对一绑定，仅提供有权限访问且店铺启用的商品；已停用商品会标注状态，已从物流费列表删除的商品仍可选以重新添加。选中 SKU 后自动显示所属店铺，不再手工选择适用范围，保存时后台重新校验并确定店铺。未绑定或品牌对应多个店铺时须先完善档案。修正旧版本保留原范围；全部店铺视图按各 SKU 归属店铺展示适用费用，缺少专用费用时回退通用费用。

SKU 行末的「删除」清除当前范围内可管理的全部双档物流费版本（含历史及未来版本）。选择店铺时范围为该店铺及通用费用，全部店铺时为所有可见范围；通用费用仅管理员可清除。确认框显示 SKU、范围和版本数量，后台检查整个版本集合，新增、修改或删除造成的变化均要求刷新确认，删除逐版本记入审计日志。即使调价记录为 0 个版本也允许删除。删除后整行从当前范围的列表中移除，商品、订单及历史单档成本保留，刷新、切换状态或重新导入订单不会使其重新出现。通过“新增物流费”主动添加该 SKU 可恢复展示。删除通用费用会影响其他使用通用费用的店铺。

每个 SKU 的物流费版本独立保存适用范围、生效日期、两个单件费用和来源备注：

- **售价 ≤ $9.99**（包含 9.99）与 **售价 > $9.99** 各录入一个单件物流费，单位 USD。两档均必填，0 表示明确无费用，不把未知值当作 0。
- 售价使用用户确认的 **订单商品金额 ÷ 数量，优惠前、不含税和运费**。非美元订单按当前销售分析的固定汇率折算 USD；比较时不提前四舍五入。同日同 SKU 的不同售价订单逐条判档，再汇总费用，不使用日均售价。
- 新价格用「新增调价」录入新的生效日期。相同范围、同 SKU 只能有一个同日版本；旧版本自动截至下一个版本开始的前一天，首尾日期均包含。最后一个版本持续至下次调价，可提前录入未来价格，也可插入历史中间版本，自动重算相邻期间。
- 订单按 UTC 下单日期匹配当时生效的版本。店铺专用版本优先于通用版本；物流费的生效日期独立于产品成本和佣金，调价不会复制或改写其他成本。
- 「历史版本」显示各范围的起止日期和两档费用。修正已有版本会重算该版本适用期间，保存检查 revision 防止旧页面覆盖他人修改；不同日期的新增版本保留历史。
- 现有单档费用保持原样，没有适用双档版本的订单仍沿用原成本档案的 FBA 单价。不会把旧单档值擅自填成两个档位；用户首次录入后，从指定日期开始使用新规则。
- 双档物流费按订单原始 SKU 精确匹配，CMBQ 各尺寸可分别维护物流费；分析展示和产品成本仍沿用原尺寸归并规则。缺少商品金额时无法判断档位，物流费及相关利润留空；数量为 0 时费用为 0。
- 「查看日期」可查询当日适用价格；顶部选择全部店铺时展示通用价格，选择单店时展示专用优先后的价格。历史期间按各范围分别显示。权限和审计沿用现有成本维护规则。

## API 与验证

- `GET /api/v1/sales-analysis`：分页 `items`、全筛选 `totals`、排除的币种行数；支持 store_id、start_date、end_date、sku、q、order_scope、sort_by、descending。可重复传入 excluded_keys（行 key，店铺 ID + 冒号 + SKU），仅从合计中排除指定行，列表、排序与分页总数不变；利润率按纳入合计的利润与销售额重算。
- 页面请求传 exclude_incomplete=true，使全部分页中有 issues 的 SKU 默认不计入合计；included_keys 可重复指定手动勾选的待补充行，excluded_keys 仍优先排除手动取消的行。省略 exclude_incomplete 时保持原接口的全筛选合计口径。
- SKU 列内的「计入合计」复选框对资料完整行默认勾选，资料待补充行默认不勾选，可手动调整。合计行及上方统计覆盖所有分页内勾选的 SKU；翻页、排序保留勾选状态，切换店铺、日期、搜索、订单范围或汇率后恢复默认勾选。SKU 列宽为 200px，表头、SKU、销量及展开按钮在滚动时固定。
- `GET /api/v1/sales-analysis/periods`：要求 store_id、sku，支持日期、订单范围、汇率以及 granularity=day/week/month/year；返回按期间升序的分页明细、period_start 和 period_end，权限与主分析一致。
- `GET /api/v1/sales-analysis/suggestions`：销售与广告 SKU 并集候选，遵守店铺权限与期间筛选。
- `GET /api/v1/sales-analysis/costs`：可见费用版本列表。
- `POST /api/v1/sales-analysis/costs`：以 scope + sku + effective_from 保存费用版本，revision=0 表示新增；编辑必须传当前 revision。
- `DELETE /api/v1/sales-analysis/costs/{id}`：删除指定成本与佣金版本，必须传当前 revision；通用版本仅管理员可删除，店铺版本须有 `quotes.manage` 及店铺授权。
- `GET /api/v1/sales-analysis/fba-fees/catalog`：分页 SKU 目录，支持 store_id、as_of、q、is_active（省略时返回全部）；包含当日费用、历史单档参考值、版本数、未来版本数及可删除版本映射 deletable_versions。
- `DELETE /api/v1/sales-analysis/fba-fees/catalog`：传 sku、store_id 和 versions（版本 ID 到 revision 的映射），原子删除 SKU 列表行并清除该范围内可管理的全部版本，versions 可为空；版本集合变化时返回 409。行删除独立记录于 fba_catalog_deletions，并写入 sales.fba_sku.delete 审计。所选店铺删除仅移除该店铺列表行；管理员全部店铺删除移除所有范围，其他账号全部店铺删除移除其授权店铺范围。所有可见店铺均移除后，汇总列表也不再展示。
- `GET /api/v1/sales-analysis/fba-fees`：按 sku、store_id 查询可见历史版本，effective_until 为同范围内自动计算的含当天截止日期，null 表示至下次调价。
- `GET /api/v1/sales-analysis/fba-fees/sku-options`：分页返回唯一归属授权启用店铺的商品 SKU、商品名称及所属店铺，支持 store_id 筛选。
- `POST /api/v1/sales-analysis/fba-fees/by-sku`：按商品品牌自动确定店铺并保存费用版本，传 sku、生效日期、双档费用、来源及 revision；不接受 store_id。
- `POST /api/v1/sales-analysis/fba-fees`：独立保存两档物流费，字段 low_price_fee、high_price_fee 均必填，revision=0 新增，编辑传当前 revision。
- `DELETE /api/v1/sales-analysis/fba-fees/{id}`：删除指定历史版本，传当前 revision；版本被修改时拒绝删除并要求刷新。权限与维护一致，通用版本仅管理员可删除，授权店铺版本要求 `quotes.manage`。记录删除审计日志。

「物流费历史版本」每行提供删除入口，确认框展示 SKU、适用范围、生效期间及两档费用。删除后同范围前一版本自动延续至下一版本前一天；没有更早版本时，按原规则回退通用或历史单档费用，均缺失则标记缺少费用。目录、历史期间和适用订单的利润分析同步更新。需要恢复时重新新增该日期的费用版本。
