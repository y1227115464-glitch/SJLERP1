# 销售数据分析

品牌推广广告日报也参与实际广告费：请先在「广告数据 → 品牌广告分摊」按店铺和活动名称维护 SKU 与百分比（合计 100%）。配置应用于全部历史及后续日报；未配置活动会显示待分摊金额，并将受影响店铺的实际广告费和推广后利润留空。详见 [品牌推广导入和分摊规则](amazon-report-imports.md#品牌推广活动报告)。

原「销售记录」入口改名为「销售数据分析」。包含「销售数据分析」与「订单明细」两个页签，原订单查询、币种/状态核对和来源批次追溯继续保留。

## 数据与筛选

- 数据来自已确认导入的销售订单、广告日报，不写入示例经营数据。
- 按店铺、日期、精确 SKU 或 SKU 关键词筛选；销量、销售额、利润、利润率及广告费可排序。
- 默认只统计订单状态为 Shipped / Partially Shipped、商品状态为 Shipped 的明细；可切换「全部未取消商品」，两种模式均排除订单或商品状态为 Cancelled / Canceled 的记录。
- 订单按 UTC 下单日期筛选，广告按来源日报日期筛选。USD 保持原值，CAD、MXN 按页面显示的固定分析汇率折算，销售和广告使用相同汇率。默认沿用周利润口径 1 USD = 1.36 CAD / 17.66 MXN，可针对当前分析调整；不是实时汇率。不支持或缺少币种的来源行数单独提示。
- 店铺与 SKU 联合分组，广告存在但没有订单的 SKU 仍会显示。沿用已确认周利润规则：CMBQ-XXL-250S、CMBQ-XXXL-250S、CMBQ-XS-250S、CMBQ-M-250S、CMBQ-S-250S、CMBQ-XL-250S 归并为 CMBQ-L-250S，费用也统一维护；可展开查看原始 SKU。其他 SKU 精确关联，不推断相似名称的对应关系。gfss 两种颜色保持独立。
- 广告使用已导入日报，历史多日区间汇总不再叠加。没有任何广告日报的店铺/所选期间，广告费用及广告后利润留空；已有日报中未出现的 SKU 广告费显示 0。系统不能据此证明每一天报表都完整，使用者需核对导入期间。

## 计算口径

所有单件费用单位 USD，使用 Decimal 计算。每个店铺 SKU 的费用与销售额先汇总再四舍五入至分，利润使用这些分位金额相减，合计为全部筛选行相加。

| 列 | 公式 / 来源 |
| --- | --- |
| 店铺 SKU | 同店铺内按上述归并规则汇总 Seller SKU |
| 销量 | 所选订单商品行 quantity 之和 |
| 产品成本、头程及入库配置费 USD | 按下单日适用单件成本及另计入库费 × 对应销量 |
| FBA 派送费 USD | 每条订单按优惠前单件售价选择 ≤ $9.99 或 > $9.99 档位，再按下单日适用单件物流费 × 对应数量汇总 |
| 亚马逊佣金 USD | 商品销售额 × 对应费用版本佣金率，未配置时默认预估 15% |
| 销售利润 USD | 销售额 − 产品成本/头程/入库费 − FBA 派送费 − 佣金 |
| 亚马逊销售额 USD | 商品金额 − 商品优惠；原行金额不再次乘销量 |
| 销售利润比（未扣除推广费用） | 销售利润 ÷ 销售额 |
| 实际广告费 USD | 同店铺、SKU 与所选期间广告日报 spend 之和 |
| 扣除推广实际利润 USD | 销售利润 − 实际广告费 |
| 实际利润率 | 扣除推广实际利润 ÷ 销售额 |

销售额不含运费、礼品包装费和税，与「订单明细」中的不含税订单净额口径不同。广告归因销售额不叠加到订单销售额。此分析仍使用成本与派送费参数、预估佣金，不能作为实际结算/月结利润。订单导出不能完整表达结算退款与其他费用。

SKU 销售与利润列表每页显示 200 条，不足 200 条时显示实际数量。合计按全部筛选结果计算，不受分页影响；合计利润率以合计利润除以合计销售额重算，不平均 SKU 利润率。销售额为 0 时利润率按约定显示 0。缺少销售额、单件成本、入库费确认或派送费时，受影响金额与利润保留为空，合计相应字段也为空，避免用部分成本高估总利润。

## 费用维护

点击「费用设置 → 产品成本与佣金」，可按 SKU 搜索、添加生效日期版本、编辑现有版本。每个版本包含：适用店铺（或通用）、精确 SKU、生效日期、产品及头程单价、另计入库费、佣金率和来源说明。原 FBA 单价作为历史单档费用保留展示，新物流费在独立页签维护。

- 下单日存在店铺专用版本时优先使用该版本，否则使用通用版本；分别选择不晚于下单日的最近生效日期。
- 专用版本有空值时不从通用版本补值，以免混用来源。留空表示未知；确认无费用时填写 0。
- 产品单价已经包含入库费时，另计入库费填 0。
- 新增生效日期保留先前成本口径；修改现有版本会重算该版本的适用期间。并发修改检查版本号，旧页面提交会收到刷新提示。
- 查看分析与费用要求 reports.view 和 costs.view；运营仍可看订单明细。管理员可维护通用费用；有 quotes.manage 的经理和财务可维护授权店铺费用。写入要求会话 CSRF 校验并记录审计，审计摘要不显示金额。

### 亚马逊物流费（按售价分档）

左侧「亚马逊物流费」提供所有商品的维护入口，也可从「费用设置 → 亚马逊物流费」进入。列表包含商品档案 SKU、可见订单及广告 SKU、已维护成本与物流费 SKU；没有订单或没有费用的商品也可以维护。列表按原始 SKU 精确匹配，不自动推断商品内部 SKU 与不同 Seller SKU 的关系。

每个 SKU 的物流费版本独立保存适用范围、生效日期、两个单件费用和来源备注：

- **售价 ≤ $9.99**（包含 9.99）与 **售价 > $9.99** 各录入一个单件物流费，单位 USD。两档均必填，0 表示明确无费用，不把未知值当作 0。
- 售价使用用户确认的 **订单商品金额 ÷ 数量，优惠前、不含税和运费**。非美元订单按当前销售分析的固定汇率折算 USD；比较时不提前四舍五入。同日同 SKU 的不同售价订单逐条判档，再汇总费用，不使用日均售价。
- 新价格用「新增调价」录入新的生效日期。相同范围、同 SKU 只能有一个同日版本；旧版本自动截至下一个版本开始的前一天，首尾日期均包含。最后一个版本持续至下次调价，可提前录入未来价格，也可插入历史中间版本，自动重算相邻期间。
- 订单按 UTC 下单日期匹配当时生效的版本。店铺专用版本优先于通用版本；物流费的生效日期独立于产品成本和佣金，调价不会复制或改写其他成本。
- 「历史版本」显示各范围的起止日期和两档费用。修正已有版本会重算该版本适用期间，保存检查 revision 防止旧页面覆盖他人修改；不同日期的新增版本保留历史。
- 现有单档费用保持原样，没有适用双档版本的订单仍沿用原成本档案的 FBA 单价。不会把旧单档值擅自填成两个档位；用户首次录入后，从指定日期开始使用新规则。
- 双档物流费按订单原始 SKU 精确匹配，CMBQ 各尺寸可分别维护物流费；分析展示和产品成本仍沿用原尺寸归并规则。缺少商品金额时无法判断档位，物流费及相关利润留空；数量为 0 时费用为 0。
- 「查看日期」可查询当日适用价格；顶部选择全部店铺时展示通用价格，选择单店时展示专用优先后的价格。历史期间按各范围分别显示。权限和审计沿用现有成本维护规则。

## API 与验证

- `GET /api/v1/sales-analysis`：分页 `items`、全筛选 `totals`、排除的币种行数；支持 store_id、start_date、end_date、sku、q、order_scope、sort_by、descending。
- `GET /api/v1/sales-analysis/suggestions`：销售与广告 SKU 并集候选，遵守店铺权限与期间筛选。
- `GET /api/v1/sales-analysis/costs`：可见费用版本列表。
- `POST /api/v1/sales-analysis/costs`：以 scope + sku + effective_from 保存费用版本，revision=0 表示新增；编辑必须传当前 revision。
- `GET /api/v1/sales-analysis/fba-fees/catalog`：分页 SKU 目录，支持 store_id、as_of、q；包含当日费用、历史单档参考值、版本数和未来版本数。
- `GET /api/v1/sales-analysis/fba-fees`：按 sku、store_id 查询可见历史版本，effective_until 为同范围内自动计算的含当天截止日期，null 表示至下次调价。
- `POST /api/v1/sales-analysis/fba-fees`：独立保存两档物流费，字段 low_price_fee、high_price_fee 均必填，revision=0 新增，编辑传当前 revision。
- 数据库迁移 `79ec620ba134` 新增 sales_cost_rates 表；不修改订单或广告事实。
- 数据库迁移 `83b1d6079a25` 新增 fba_fee_rates 表，不改写旧单档费用，也不预填新的业务价格。
