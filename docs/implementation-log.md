日期：2026-09-07 至 2026-09-08。状态：首批基础功能已可运行，前后端联调及本地验证已完成。M1 中依赖业务档案和报表的剩余项已在执行计划中明确保留。

### 本轮任务分工

| 工作 | 负责方式 | 交付位置 |
| --- | --- | --- |
| 后端、数据迁移、账号权限和后台任务 | 后端子 agent | `apps/api/` |

| 权限与任务一致性复核 | 独立安全复核子 agent | 复现后由后端修复并补回归 |
| 运行环境、接口联调、实际数据库验收和文档 | 主 agent | `scripts/`、`infra/`、项目文档 |

### 已实现的能力

- 真实 PostgreSQL 数据库及 Alembic 初始迁移；配置从环境读取，提供项目独立启动方式。
- 内部账号登录、HttpOnly 会话、退出、过期、CSRF/Origin 校验及登录失败限流。
- 账号创建、密码重置、角色/店铺授权、停用和会话撤销；管理员防自锁。
- 店铺档案维护和权限内 CSV 导出，支持多个店铺，保护导出中的公式字符。
- 按角色、店铺、本人私有范围控制查询、下载、日志和后台任务。
- 私有附件上传下载、站内通知、操作审计和审批查询数据基础。
- 独立 RQ worker 执行 `workspace_check`，任务状态持久化、队列恢复调度、失败重试和结果去重。
- 中文后台连接真实 API；尚无订单、广告及库存数据时保留明确空状态。

### 范围与限制

- 当前角色为固定的公司管理员、店铺主管、运营、财务和仓库；公司管理员拥有全部店铺范围。独立主体档案和具体业务敏感字段会随 M2/M4 模型继续接入和验证。
- 当前实际后台任务是基础资料与附件可访问性检查。订单、广告和库存的导入解析器尚未实现。
- 审批只有数据与权限查询基础，采购审批流由 M5 实现。
- 经营日期控件仅预留上下文，尚无经营数据时不据此展示虚构报表。
- 本轮使用本地独立 PostgreSQL 18.6 和 Redis 8.2.9 验证；电脑没有 Docker，因此容器启动尚未实测。Compose 当前提供本地数据库/队列设施，不是生产部署包。
- 原一期、二期的完整 ERP 仍按 M2–M8 推进；没有将采购、物流、财务月结移出范围。
