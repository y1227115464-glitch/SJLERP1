# 亚马逊销售与广告导入

当前支持用户提供的亚马逊订单 TXT 和中英文「商品推广－推广的商品」（Sponsored Products Advertised product report）XLSX 格式。无需另填模板或修改表头。

2026-09-09 [灵活作业设计](weekly-operations-workflow.md) 规划每天15:00下载经营数据和周五销售/库存分析待办，并保留商品周表、报告时区/覆盖、版本及FBA快照等后续能力。提醒可改期或取消，随时可以导入/分析，不以待办完成作为前置；这些增强尚未实现，下文仍记录当前导入及日期筛选行为。

## 操作步骤

1. 打开「数据导入中心」，选择「导入销售数据」或「导入广告数据」。
2. 选择文件实际所属店铺并上传原始报告。文件最多 20 MB、10000 行。
3. 查看新增、更新、跳过、冲突和文件内重复数量；可筛选预览行，错误标注源行号。
4. 核对后点击「确认导入」。有错误或冲突时整批不写入，修正后重新上传。预览后其他人更新了数据，系统会要求刷新预览并再次确认。
5. 在「销售数据分析 → 订单明细」或「广告数据」查看明细、搜索、日期和店铺筛选，以及币种汇总。点击记录可查看规范字段，点击「批次 · 行」可追溯来源。SKU 销量和推广前后利润见 [销售数据分析](sales-analysis.md)。

上传和预览会保存批次，但不会改动销售或广告记录。确认后的批次保留处理数量和来源；再次点击确认或网络重试不会重复入库。文件内相同行的合并数量与「跳过已有」分别展示。

导入批次、导入数据详情、销售及广告明细等分页列表统一每页显示 200 条；不足 200 条时显示实际数量。

首次查看默认全部日期。销售按 UTC 下单日期筛选；广告默认显示「日报」，按源报告日期筛选。旧版多日汇总可切换「历史区间」查看，其区间须完整落在筛选范围内，不拆成日报，也不与日报合计。

点击「日期」区间输入框展开双月日历，按顺序选择开始和结束日期，选完自动应用并关闭。输入框显示 `YYYY/MM/DD → YYYY/MM/DD`，也支持直接输入日期。弹层左侧提供 **最近7天、最近3天、今天、最近30天、本周、上周、本月、上月、今年以来** 九个快捷入口，点击后立即应用。已有 SKU/关键词、店铺、状态和广告粒度筛选继续生效。

快捷区间按浏览器所在设备的本地日历计算。左侧「含当天」默认勾选，控制最近 3/7/30 天是否包含今天；取消后最近 N 天截至昨天，不改变「今天」及周/月/年等固定周期。每周从周一开始，本周、本月和今年以来截至今天，上周取完整周一至周日，上月取整月。手动选定区间会取消快捷高亮；点输入框清除按钮或「全部日期」恢复全部记录。未完成的手选可按 Esc 取消；只改一端后再选快捷项，以最后选中的快捷范围为准。

## SKU 候选搜索

销售订单明细和广告数据共用相同的搜索方式：

1. 点击空搜索框，显示当前授权店铺、日期及状态/广告粒度范围内的去重 SKU 列表。
2. 输入内容后，候选按 SKU 包含匹配，大小写不敏感；输入过程中明细和汇总保持原查询结果。
3. 点击候选或用方向键选中后按回车，立即按该 SKU 精确搜索明细和汇总，例如选择 `SKU-A` 不会包含 `SKU-AB`。
4. 也可直接按回车或点击搜索按钮，确认普通关键词搜索；点击输入框的清除按钮恢复全部记录，其他筛选条件仍生效。

候选最多显示 50 个，超过时会提示继续输入缩小范围。无匹配 SKU 时仍可确认关键词，搜索订单号、ASIN、商品名称或广告活动等原有字段。广告「日报」与「历史区间」各自提供对应数据中的 SKU。

## 销售格式与重复处理

支持 UTF-8（含 BOM）或 UTF-16 编码的制表符 TXT/TSV。必需列：

```text
amazon-order-id, purchase-date, last-updated-date, order-status,
fulfillment-channel, sales-channel, product-name, sku, asin,
item-status, quantity, currency, item-price
```

同时保留 order-item-id（订单明细编号）、merchant-order-id、商品税费、运费及运费税、包装费及包装税、商品优惠和运费优惠。表头前后空格会清理；明细编号作为文本保留前导零；数量必须是非负整数，时间必须带时区；金额按四位小数保存，缺失金额保留为空。

提供订单明细编号时，销售身份为 **店铺 + sales-channel + amazon-order-id + order-item-id**，同订单同 SKU 的不同明细分别保存，金额相同、零金额或已取消也不会合并。没有明细编号的旧格式仍以 **店铺 + sales-channel + amazon-order-id + sku** 识别。两者均与文件名和上传账号无关。同文件同订单同 SKU 的编号部分缺失时拒绝导入，请使用完整的原始报告。

| 情况 | 处理 |
|---|---|
| 同文件内相同身份、相同规范内容 | 合并，只保留一行 |
| 同文件内相同身份、内容不同 | 报冲突；有明细编号时提示对应源行，无编号时不猜测为同 SKU 拆行 |
| 已有相同身份、相同内容 | 跳过，不增加数量或金额 |
| 已有相同身份，新报告更新时间更晚 | 更新原记录及来源，不新建第二行 |
| 已有相同身份，新报告更新时间更早 | 跳过，保留较新记录 |
| 已有相同身份，更新时间相同但内容不同 | 报冲突，整批暂不导入 |

因此相同文件、改文件名和重叠日期导出的文件都能去重。不同店铺或销售渠道保留独立身份。缺少 order-item-id 时遇到同订单同 SKU 的不同拆行仍须核对来源，不自行合并金额。

历史兼容：预览时按旧记录的来源批次和源行，在校验原文件哈希及规范内容后恢复明细编号。确认时原位补全身份或更新该明细，避免旧记录与新记录重复计数；只补编号时保留原数量、金额、更新时间和来源。原文件缺失或未含编号时，仅允许本批存在唯一一条与历史规范内容完全相同、且没有其他已编号历史明细的记录对应升级；无法唯一对应时整批报冲突，不根据金额加总或时间较新猜测。已有带编号明细后，缺少编号的同订单同 SKU 报告不能覆盖或另行新增。历史同内容拆行被合并的缺失明细可通过重新上传完整原文件补回。

销售解析版本为 `amazon-sales-v2`。升级前尚未确认的销售批次必须重新上传原文件，旧预览不能直接确认；已确认批次保留原结果供追溯。明细编号保存在现有规范数据中，本次不需要数据库结构迁移。

不含税净额 = item-price + shipping-price + gift-wrap-price − item-promotion-discount − ship-promotion-discount。item-price 是源行金额，**不再乘 quantity**。无商品金额时净额为空；取消或待处理订单按状态分组，币种为空时展示「未提供」。USD/CAD 等币种分别汇总。这里展示订单报告金额，不是结算收入或利润。

## 广告格式与重复处理

### 品牌推广活动报告

「导入广告数据」同时支持 **Sponsored Brands Campaign report / 品牌推广_广告活动_报告** 的中英文 XLSX，可混用表头、调整列顺序，保留 **14 天归因**。识别日期、活动名称、组合、币种、国家、费用类型（CPC / VCPM）、展示、点击、花费和 14 天总销售额/订单数/销量。点击归因、视频及品牌新客等额外列不参与基础指标计算，不会误用点击销售额替代总销售额。

品牌推广不要求 SKU、ASIN 或广告组；按 **店铺 + 日期 + 广告活动名称** 去重，新报告覆盖旧指标，文件内重复日报保留最后一行。品牌推广与商品推广的业务键独立，同名活动不会互相覆盖；不同店铺也独立。同名活动的国家、币种、费用类型改变视为属性更新。名称改变视为新活动。

在 **广告数据 → 品牌广告分摊** 维护活动对应的商品列表和百分比。导入后活动自动出现，也可提前新增配置：

1. 选择店铺，填写与报表完全一致的活动名称。
2. 选择商品或填写订单中的 Seller SKU；内部商品编号不一致时以 Seller SKU 为准。CMBQ 尺寸别名沿用利润分析归并规则。
3. 每个 SKU 比例大于 0，最多四位小数，合计必须为 **100%**；重复 SKU（含归并后重复）不能保存。
4. 保存后配置应用于该活动全部历史和后续日报，不改写原报告金额。多人同时编辑时，后保存者须刷新后重试。

销售分析将品牌广告日报花费按配置分摊到 SKU，与商品推广花费一起扣减利润。按所选期间、活动和币种汇总花费后转换 USD，使用最大余数法分配到分，确保每项活动分摊总额与舍入后的花费相等；SKU 筛选在分摊后应用。广告归因销售额不加入订单收入。多日区间仍仅在历史区间查看，不参与每日利润。

所选期间如有品牌活动未配置，会列出待分摊活动及原币花费，并将该店铺 SKU 的实际广告费、推广后利润和受影响合计留空，避免漏扣费用。零花费活动也显示待配置，补齐后即可计算。配置按店铺隔离，查看需要 `reports.view`，维护需要 `reports.import`，停用店铺不能修改。

广告明细支持广告类型筛选；汇总按币种和广告类型分组，明确显示商品推广 7 天和品牌推广 14 天窗口。

上传预览、历史批次及广告明细的「SKU / ASIN」会按当前店铺和活动分摊配置展示多个商品及比例。ASIN 优先读取 SKU 对应的商品档案，缺失时从该店铺销售记录匹配；无匹配时明确显示「ASIN 未匹配」。这些展示关联不会改写原报告字段或改变去重结果。比例调整后刷新即可看到新配置，无需重新导入。

每行提供「删除分摊」，确认后从默认列表移除并停止应用该活动的商品比例；待配置活动也可删除，再次导入同名广告不会使其重新出现。原始广告报表、花费和导入批次仍保留，相关花费在利润分析中显示待分摊。打开「显示已删除」，点击「恢复并维护」并保存有效比例即可恢复；原配置会保留供恢复时使用。删除、恢复均按店铺权限和版本校验，并记录操作日志。

### 商品推广商品报告

支持一张工作表的 XLSX，使用「日期」列，或相同的「开始日期」「结束日期」表示日报。支持对应英文表头 Date、Start Date、End Date，以及广告组合、货币、活动、广告组、零售商、国家/地区、广告 SKU/ASIN、展示、点击、花费、7 天总销售额/订单数/销售量、广告 SKU 与其他 SKU 的销售额/销售量的中英文表头。导入时自动映射到相同字段，清理表头前后空格并忽略英文大小写；允许中英文混用和调整列顺序。同一字段同时出现中英文列名仍视为重复列并拒绝导入，14 天等其他归因窗口不会映射为 7 天。可读取 Excel 日期和 YYYY-MM-DD；兼容旧样本错误的工作表范围信息。日期列和起止日期同时出现时必须一致。

日报去重身份为 **店铺 + 日期 + SKU + 广告活动名称 + 广告组名称**，保留 **7 天归因窗口**：

- 同一天、同 SKU、同活动和广告组：新导入覆盖旧指标与属性，不能累加；相同内容跳过。ASIN、币种、国家、零售商和组合变化仍更新同一条记录。
- 不同日期、店铺、SKU、活动或广告组分别保存。同一文件内重复时保留最后一行，预览显示「文件内合并重复行」和最后源行号。
- 更晚上传且已确认的报告优先；即使指标相同而跳过，也会记录最新确认的上传时间，防止较早待确认批次覆盖它。报告本身不含生成时间，重新上传一个旧文件仍视为新上传版本，确认前需核对指标。
- 活动/广告组名称属于身份，重命名视为不同记录，当前不能自动关联。

旧版起止日期不同的多日汇总继续按原维度与完整区间处理，仅在「历史区间」查询和汇总：相同身份同区间替换，不同重叠区间拒绝。本次迁移将旧单日记录转为日报并去重，按最新上传版本、同批次最后源行保留，原确认批次留存追溯。新版上线前尚未确认的广告批次需要重新上传，避免沿用旧去重键；已确认的批次仍可查看。

汇总按币种分别计算：CTR = 点击 / 展示，CPC = 花费 / 点击，ACOS = 花费 / 归因销售额，ROAS = 归因销售额 / 花费。零分母显示为空；不直接平均报告中的比率。广告归因销售额独立展示，不加到订单销售额。

## 权限、文件与边界

### 删除导入批次及数据

在「数据导入中心」的批次列表或批次详情点击「删除批次及数据」。确认框会先显示店铺、文件和实际影响的记录数：

- 未确认、校验有误的批次只移除预览，不影响已入库记录。
- 已确认批次会移除当前仍以此批次为来源的销售或广告记录，销售/广告汇总及利润分析随之重新计算。删除未分摊品牌广告的全部来源数据后，该活动的待分摊提示也随之消失。
- 重复导入时跳过的记录仍归属原来源批次；后续批次更新的记录归属后续批次。因此删除数可能少于源文件行数，删除旧批次不会移除这些其他来源记录，也不会恢复被覆盖的旧版本。
- 默认列表隐藏已删除批次，打开「显示已删除」可查看历史来源及删除数量。保留原文件和审计日志供追溯，已删除批次不能再次确认；恢复业务数据须重新上传并确认原文件。
- 删除要求 `reports.import` 权限、当前店铺授权及启用状态；确认删除与确认导入使用同一店铺锁。预览后批次或关联记录变化时拒绝删除，刷新核对后重试。

品牌广告分摊配置独立保留，方便后续重新导入继续使用；「删除分摊」本身仍不会删除广告花费。

管理员、店铺主管、运营和财务可在授权店铺内查看、导入；只有上传者可确认自己的批次。仓库角色没有报表权限。店铺停用或授权被撤销后不能继续确认。

原始文件以随机存储名保存在配置的私有文件目录，文件权限为 600，不作为公开附件提供下载。页面及报表 API 仅返回规范业务字段，不返回原文件中的收件地址、邮编或买家标识。备份报表需同时备份数据库和私有文件目录。

禁止宏、公式和损坏的 XLSX；解压最多 50 MB、1000 个文件项；表最多 80 列。解析失败或确认冲突不会部分写入事实表。

商品推广按原 Seller SKU/ASIN 保存，品牌推广通过活动配置关联利润分析 SKU；导入不会扣库存。利润计算见销售数据分析。除上述商品推广 7 天、品牌推广 14 天外的窗口，以及搜索词、结算、库存快照及退款等报告需另行适配。正式导入请由用户选择实际店铺并确认。
